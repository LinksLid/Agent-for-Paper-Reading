# 人工评测与课堂演示清单

这是待团队执行的评测方案，不是已经获得的人工成绩。问题由本次项目目标整理；参考答案、页码与评分需要成员阅读原文后补齐，不能直接把系统自己的核验当作标准答案。

## 统一实验条件

比较三种设置：A 单阅读者，B 方法/实验分工但不返工，C 分工并核验返工。优先使用MAC-SQL与CHESS这组同领域论文；机制题再使用Multiagent Debate、Self-Refine、ToT。每一题三种设置必须使用相同PDF哈希、检索证据池、模型版本、输出格式与事实性结论上限。记录输入/输出token与实际耗时；若C的额外调用不能匹配预算，报告质量与成本两列，不宣称等预算提升。

建议每题输出至多6条结论，每条附paper_id、页码/chunk_id、短引文、明确的适用条件与无法确认项。将额外“逐篇教学讲解”关闭或对全部设置统一开启，避免把额外上下文差异算成协作收益。固定随机参数并重复3次，保留失败和未完成项。

## 评分表与成本

| 指标 | 计算与注意点 |
|---|---|
| 事实正确率 | 正确且可核验的原子事实主张数 / 全部事实主张数；无法支持、数字错误与条件遗漏分别记错因 |
| 证据支持率 | 能定位且语义支持对应结论的引用项 / 需要引用的项；“引文确实存在”不等于支持结论 |
| 要点覆盖率 | 覆盖的人工参考要点 / 全部参考要点；部分覆盖规则须评分前固定 |
| 比较合理性 | 对预先标出的不可直接比较项，统计正确识别数量及漏报/误报 |
| 运行成本 | 实际耗时、输入/输出token、模型请求数、失败/解析失败/返工次数，保留全体样本 |

每题记录：题号、匿名配置、重复序号、参考答案版本、正确/错误/无法确认主张、支持/不支持引用、覆盖要点、比较限制、token、耗时、失败与评分人。两位评分人先独立判断，再记录分歧如何解决。模型核验员的accepted字段不得直接填入人工正确列。

## 5分钟课堂演示

1. 约40秒：用一句话说明目标——把多论文结论、原文证据与可执行实验连接起来；展示角色协作示意。
2. 约70秒：从保存的真实阅读记录选一条退回项，展示结论、页码/片段、退回理由以及后续修改或排除。不要将未修复的条目说成已修正。
3. 约80秒：展示MAC-SQL 5/6的逐题结果、ReAct 1/2的一段真实环境轨迹，明确小样本与替换模型。
4. 约60秒：展示辩论评分的格式错误，或“命令超时但产物保留”的修复证据；说明这是工程兼容改进。
5. 约50秒：用人工质量与成本表总结收益/代价；若人工评测未做，明确列为未完成，展示下一步方案。

现场演示使用保存记录并标注运行时间与模型，提前录屏。需要实时调用时先检查API、Docker和预算，预留失败时切换保存记录的入口。
