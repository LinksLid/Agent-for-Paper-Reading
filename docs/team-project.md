# 六人分工与课堂汇报

## 项目目标

围绕给定问题阅读多篇论文，生成带原文依据的中文报告；逐篇搜索与核对 GitHub，下载原仓库，检查依赖、数据、模型并尝试执行原实验。用户已有五篇论文横跨 Text-to-SQL、数据准备、推理行动和视觉指令，不应强行比较它们的任务指标。阅读主线可选 MAC-SQL 与 CHESS；实验演示使用 MAC-SQL 的官方 BIRD 数据子集及 ReAct 的官方 ALFWorld 文本任务。依赖实时 Wikipedia 的实验先检查服务可用性。

## 六人开发分工

| 成员 | 核心责任 | 对应文件与交付 |
|---|---|---|
| 1 | 总体架构、集成和 API 配额优化 | `workflow.py`、`runner.py`、实际运行图 |
| 2 | PDF 解析与证据检索 | `corpus.py`、页码定位与检索评测 |
| 3 | 阅读规划与方法分析 | Plan、方法提示词、方法阅读卡片 |
| 4 | 实验分析与证据核验 | 实验提示词、Review、错误与补查案例 |
| 5 | 实验复现 | `repositories.py`、`repository_experiments.py`、`experiment_runtime.py`；仓库核验、原实验运行与日志 |
| 6 | 交互、综合报告与评测组织 | `app.py`、报告导出、人工标注和演示 |

每位成员都应理解自己的代码、运行本模块、检查样例并参与报告，不能只按角色名分配 PPT 页面。

## 对应课程六项要求

1. **任务目标、背景和原因**：论文篇幅长，跨论文比较困难，生成式总结可能缺少依据；目标是把结论、原文和本机实验连接起来。
2. **团队角色分工**：展示上表，补充实际成员姓名与提交记录。
3. **框架与协作流程**：解释 LangGraph 的 State、Node、Edge、并行汇合、条件返工和 SQLite 检查点；展示本次运行生成的 `workflow.mmd`。
4. **核心难题（选 2～3 个）**：原文证据与语义核验；官方数据与容器环境适配（路径、未发布版本、编译依赖、原代码吞掉异常）；旧 Completion 续写语义与聊天模型的格式差异。展示真实失败日志、修复和对照，区分工程兼容与算法改进。
5. **运行结果**：展示报告、证据定位、退回及补查、逐篇仓库与提交、原实验命令、实际产物或阻塞原因，附模型、样本数、token、时间与实验范围。旧版合成数据 SQL 成绩不能当成原论文实验复现结果。
6. **经验与反思**：分工是否带来增益要用数据判断；核验增加成本；共同底层模型有共同偏差；微型实验验证的是流程，不是论文完整指标。

## 建议的 5 分钟演示

1. 选择 MAC-SQL 与 CHESS，输入协作机制与实验设计的比较问题。
2. 展示规划、两个分析分支、核验和复现节点的完成状态。
3. 点开一条报告结论，展示 PDF 页码与原文片段。
4. 如真实运行产生过退回，展示 `review_history` 中的反馈及后续修改；若没有，不虚构修复案例。可单独说明自动测试使用错误夹具验证过该路径。
5. 展示原仓库提交、Notebook/脚本、真实数据子集、兼容性补丁、模型调用、原评估产物与范围说明；同时展示某篇论文缺少哪些数据或权重。

提前准备真实运行输出和录屏。现场接口不稳定时用保存的输出展示，并说明保存时间和模型。

## 后续优化方向

- 标注约 20 个阅读问题，测检索召回和引用支持率。
- 增加表格或图片解析，对比纯文本版本。
- 使用不同模型进行核验，观察共同偏差是否减少。
- 将已完成的 BIRD 子集实验扩展到更多数据库，补充单/多智能体消融与多次运行，而不只看单次准确率。
- CHESS 需要与原方法兼容的 embedding 及检索索引条件，不能用去掉检索模块的运行冒充原方法。
