# 评测方案与结果记录约定

## 阅读工作流

先选择同一领域的 2 至 3 篇论文，人工准备 15 至 20 个问题。每个问题保存：论文 SHA256、参考答案要点、原文页码、原文片段、是否允许跨文比较。由两名组员独立标注，分歧讨论后确定。

比较 `single`、`multi` 和 `verified` 三组，固定论文、用户问题与模型。记录每组实际看到的检索材料、调用次数、总 token 与耗时。当前程序未强制等上下文或等 token 预算，所以只做系统配置比较；若要主张某种机制更有效，需要进一步控制这些混杂因素。

| 指标 | 定义 |
|---|---|
| 事实正确率 | 人工判定正确的事实条数 / 可判定事实总条数 |
| 引用支持率 | 原文充分支持结论的引用条数 / 被抽查引用总条数 |
| 关键点覆盖率 | 报告覆盖的参考答案要点数 / 参考答案要点总数 |
| 无效比较数 | 忽略数据集、指标、划分等差异而直接排名的次数 |
| 成本 | 实际 API 请求次数、token、运行秒数；未查价格时不推算金额 |

程序中的原文连续片段校验只测引用真实性，不能自动替代上述人工语义评测。

## MAC-SQL 方法级微型实验

数据为本项目自建大学数据库，6 类问题，每个预测在两个固定数据变体上测试。记录单次基线和 Decomposer→执行→必要时 Refiner 两组。

- 官方 EX 使用 `set(predicted_rows) == set(gold_rows)`，忽略重复次数与排序。
- 补充多重集结果比较，检查重复次数；当前仍不评估排序语义。
- 只有在两个变体上都匹配才将该问题记为正确。
- 金标准只进入评估过程，不进入模型生成与修正提示词。
- 修正由 SQL 执行错误触发，不根据金标准分数触发；可执行但语义错误的 SQL 仍可能保留。
- 样本太少，且没有正式 BIRD/Spider 数据，结果只能支持流程验证。
